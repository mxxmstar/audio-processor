# 前端增强计划（Loading / 识别历史 / 子菜单）

> 本文档基于 `开发计划.md` 的已完成阶段，规划下一轮前端增强。
> 当前前端栈已迁移为 **Vue 3 + ant-design-vue 4**（Svelte 版本已废弃），Tauri 2 命令层通过 `invoke` 调用。
> 后端音频识别链路（`recognizer` 模块 + `identify` 命令）已可用，本次在其上叠加历史记录与界面优化。

---

## 目标总览

| 编号 | 目标 | 涉及层 | 优先级 |
|---|---|---|---|
| A | Loading 动画：识别 / 下载过程给出明确加载反馈 | 前端 Vue | 中 |

- [x] 失败/成功后 `a-spin` 停止，结果卡片或告警正常渲染；新增占位提示「选择音频文件并点击开始识别以查看结果」。

### A.2 下载界面 Loading（DownloadView.vue） ✅ 已完成

**阶段 A 完成标志**：识别与下载全流程均有明确 loading 反馈，无"静默等待"窗口。

## 阶段 B：SQLite 识别历史

> 目标：识别结果自动持久化，用户可在「历史记录」子菜单回顾过往识别、查看详情、删除条目。
> 不依赖外部服务，数据存于本机 SQLite 文件。

### B.1 后端：引入 SQLite（Rust）
- [ ] `Cargo.toml` 新增 `rusqlite = { version = "0.32", features = ["bundled"] }`（`bundled` 自带 SQLite 引擎，免系统依赖，Windows MSVC 需 C 构建工具）。
- [ ] 新建 `src-tauri/src/recognizer/history.rs`：
  - `HistoryRecord { id, title, artist, album, album_date, confidence, file_path, created_at }`（serde Serialize 供前端）。
  - `open_db(app_config_dir) -> Result<Connection>`：在 `app_config_dir` 下建 `recognize_history.db`（复用 `BiliState` 已注入的 config_dir；若未注入则用 `app_config_dir()` 兜底）。
  - `init_schema(conn)`：建表 `recognize_history`（含索引 `created_at`）。
  - `insert_record(conn, &SongInfo, file_path)`：写入一条；`created_at` 用 RFC3339 本地时间。
  - `list_records(conn, limit) -> Vec<HistoryRecord>`：按 `created_at DESC` 返回。
  - `get_record(conn, id)`：按 id 取单条。
  - `delete_record(conn, id)`：按 id 删除。
  - `clear_all(conn)`：清空（可选，便于调试）。
- [ ] `recognizer/mod.rs` 重导出 `history` 子模块。

### B.2 后端：Tauri 命令（commands.rs）
- [ ] `identify` 命令在 `run_identify` 成功后**自动写入历史**（调用 `history::insert_record`），保证结果不遗漏；写入失败仅告警不阻断返回。
- [ ] 新增命令（注册到 `lib.rs` 的 `invoke_handler`）：
  - `#[tauri::command] get_recognize_history(limit: Option<usize>) -> Vec<HistoryRecord>`
  - `#[tauri::command] get_recognize_record(id: i64) -> Option<HistoryRecord>`
  - `#[tauri::command] delete_recognize_record(id: i64) -> Result<(), String>`
- [ ] 命令内部通过 `app.path().app_config_dir()` 取库路径；开发期回退到 `CARGO_MANIFEST_DIR/../` 或临时目录（与 fpcalc 回退策略一致）。

### B.3 前端：历史记录视图（HistoryView.vue，新建）
- [ ] 列表用 `<a-list>`，每行展示：标题 · 艺术家 · 置信度 · 时间；右侧操作「查看」「删除」。
- [ ] 删除调用 `delete_recognize_record` 后刷新列表（`<a-popconfirm>` 二次确认）。
- [ ] 点击「查看」弹 `<a-modal>` / `<a-drawer>` 展示完整 `SongInfo`（标题/艺术家/专辑/发行日期/置信度/文件路径/识别时间）。
- [ ] 空状态用 `<a-empty>` 提示「暂无识别记录」。
- [ ] 加载历史列表时 `<a-spin>` 包裹（衔接阶段 A）。

### B.4 前端：识别后写入
- [ ] `RecognizerView.doIdentify` 拿到 `result` 后调用 `add_recognize_history`（或直接依赖后端自动写入，二选一；推荐后端自动写入，前端无需额外调用，但保留一个显式命令以便手动补录）。
- [ ] 识别成功后可 `message.success('识别成功，已存入历史')`。

### B.5 数据迁移与忽略
- [ ] `recognize_history.db` 加入 `.gitignore`（本地数据不入库）。
- [ ] 首次启动自动建表，无需迁移脚本。

**阶段 B 完成标志**：识别一次后，切换「历史记录」子菜单可见该条；可查看详情、可删除；重启应用后历史仍在。

## 实施顺序建议

```
阶段 A（Loading）── 纯前端，风险低，先做
阶段 B（SQLite）── 后端 rusqlite + 命令 + 前端视图，核心价值
阶段 C（子菜单）── 前端布局，依赖 B 的 HistoryView 已存在
```

- A 与 C 无后端依赖，可并行；B 是前提，建议优先完成 B 的后端部分再补前端。
- 全部完成后统一 `cargo build` + `npm run build` 验证。
