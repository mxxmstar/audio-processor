# FlashSR 独立依赖（专用虚拟环境 `.venv-flashsr`，Python 3.10）

**必须与 `requirements-ai.txt` 分环境安装。**
AudioSR 0.0.7 硬锁 `numpy==1.23.5`；本清单实测解析出 `numpy==2.2.6`。
两者装进同一个 venv 会互相破坏，这是本模块独立成进程的根本原因之一。

安装步骤见 `python/audio_ai_flashsr/README.md`。

```powershell
python -m venv .venv-flashsr
.\.venv-flashsr\Scripts\Activate.ps1
python -m pip install -r requirements-flashsr.txt
```

CUDA 版须先按 README 安装对应 CUDA 版本的 torch。

## 推理期真实依赖

以下版本为 2026-09-03 在 Python 3.10 + CPU 环境实测通过的组合。

```
torch>=2.6,<3        # 2.6 起 torch.load 默认 weights_only=True，见 README「权重加载」
```

## HiFi-GAN 增强版（bigvgan-48k）额外依赖

`bigvgan-48k`（前端「hifigan-48k 增强版」）复用了本 Worker 的 HiFi-GAN 后端，
但其 `BigVGANRunner` 走的是 PyPI `bigvgan` 包（而非 FlashSR 的 vendor 快照）。
`bigvgan` 顶层会 `import huggingface_hub`，因此**两者都必须装进 `.venv-flashsr`**，
否则优化 `bigvgan-48k` 时回报 `MODEL_RUNTIME_NOT_FOUND: No module named 'bigvgan'`。

`bigvgan` 在 PyPI 上声明了一堆推理用不到的重度依赖（pesq / nnaudio / tensorboard /
auraloss / ninja / matplotlib），其中 `pesq`、`nnaudio` 在 Windows 上需要本地编译、
极易失败；`matplotlib` 本项目已打桩、无需安装。因此**不要**用
`pip install -r` 直接拉全部依赖，而用 `--no-deps` 安装、其余复用本清单已装的
torch / numpy / librosa / scipy / soundfile：

```powershell
.\.venv-flashsr\Scripts\Activate.ps1
python -m pip install "huggingface_hub"
python -m pip install "bigvgan==2.4.1" --no-deps
```

> 校验：`python -c "import bigvgan; from bigvgan import BigVGAN, load_hparams_from_json, mel_spectrogram; print('ok')"`
> 该 import 依赖 `vendor_bridge.ensure_inference_only_imports()` 先桩好 `matplotlib`，
> 所以裸 `import bigvgan` 会报 `No module named 'matplotlib'` 属正常，Worker 进程内不受影响。

## 不需要安装

`matplotlib` 与 `sklearn` 虽被上游顶层导入，但只服务于训练期绘图，
`python/audio_ai_flashsr/backend.py` 已为其打桩，详见 README「依赖实测结论」。

上游 `setup.py` 声明的以下 3 项经实测（`sys.modules` 未加载）不在推理路径：

```
wandb  tensorboardX  psutil
```

以下 2 项被上游以 `try/except` 可选导入，本项目用 FFmpeg 解码、不调用
`UtilAudio.read`，无需安装：

```
torchaudio  pydub
```
