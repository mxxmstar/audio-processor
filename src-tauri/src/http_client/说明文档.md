# http_client 模块说明文档

> 模块路径：`src-tauri/src/http_client/`
> 定位：基于 `reqwest` 的轻量级 HTTP 客户端封装，用于向外部服务器（如 B 站 API）发送 HTTP 请求。

---

## 1. 模块结构

```
http_client/
├── mod.rs      # 子模块导出（client / error / types / wbi）
├── client.rs   # HttpClient 主体：连接池、GET/POST/PUT/DELETE、send 核心方法
├── types.rs    # 数据结构：HttpMethod / RequestConfig / HttpResponse / CallbackInfo
├── error.rs    # HttpClientError 错误枚举与 reqwest::Error 转换
└── wbi.rs      # 【待实现】B 站 WBI 签名（对应 Go 版 wbi.go）
```

| 文件 | 职责 |
|---|---|
| `mod.rs` | 声明 `pub mod client; pub mod error; pub mod types;` |
| `client.rs` | `HttpClient` 结构体，对 `reqwest::Client` 的封装，提供简洁请求接口，内部维护连接池 |
| `types.rs` | 请求方法枚举、请求配置（建造者模式）、响应封装、回调信息 |
| `error.rs` | 错误类型定义，实现 `From<reqwest::Error>` |

---

## 2. 已实现功能

### 2.1 客户端创建
- `HttpClient::new()` — 默认配置：连接池（最大空闲 128）、自动重定向（最多 10 次，**默认 UA 为 `HttpClient/1.0`**）、超时 30 秒。
- `HttpClient::with_builder(builder)` — 自定义 `reqwest::ClientBuilder`（用于设置代理、TLS、自定义 UA 等）。
- `HttpClient::default()` — 等价于 `new()`。

### 2.2 请求方法（便捷封装）
- `get(url)` — 发送 GET 请求
- `post_json(url, body)` — 发送 JSON 体 POST 请求（自动加 `Content-Type: application/json`）
- `put_json(url, body)` — 发送 JSON 体 PUT 请求
- `delete(url)` — 发送 DELETE 请求
- `send(config)` — **核心方法**，按 `RequestConfig` 构造并发送任意请求
- `send_expect_success(config)` — 发送并断言状态码为 200–299，否则返回 `HttpStatusError`

### 2.3 请求配置（`RequestConfig`，建造者模式）
支持链式调用：
- `.method(HttpMethod)` — 设置方法（GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS）
- `.header(k, v)` / `.headers(map)` — 设置请求头（**可用于携带 `Cookie: SESSDATA=xxx`**）
- `.query(k, v)` — 添加查询参数（`?key=value`，**WBI 签名的 `w_rid`/`wts` 由此传入**）
- `.json(body)` — 设置 JSON 请求体
- `.timeout_secs(secs)` — 设置超时（默认 30 秒）

### 2.4 响应封装（`HttpResponse`）
- `status: u16` — 状态码
- `headers: HashMap<String, String>` — 响应头
- `body: String` — 响应体（**整体读入内存**）
- `json::<T>()` — 反序列化为任意 `serde::DeserializeOwned` 类型
- `is_success()` / `is_client_error()` / `is_server_error()` — 状态码判断

### 2.5 错误处理（`HttpClientError`）
覆盖：`RequestBuildError` / `UrlParseError` / `RequestError` / `ResponseParseError` / `HttpStatusError` / `TimeoutError` / `TlsError` / `OtherError`。已通过 `From<reqwest::Error>` 自动区分超时、连接失败、解码失败等。

### 2.6 回调与日志
- `on_complete(callback)` — 注册请求完成回调，接收 `CallbackInfo`（URL、方法、状态码、耗时、响应大小）。
- 内部用 `log_info!` 打印请求开始和结束（URL、状态码、耗时、字节数）。

## 3. 适用场景评估

### ✅ 适合：调用 B 站 REST API
解析播放地址、视频信息、扫码登录等"请求-响应"式 JSON 接口完全可用：

```rust
use crate::http_client::{HttpClient, HttpMethod, RequestConfig};

let client = HttpClient::new();
let config = RequestConfig::new("https://api.bilibili.com/x/player/playurl")
    .method(HttpMethod::GET)
    .query("bvid", bvid)
    .query("cid", cid.to_string())
    .query("fnval", "4048")
    .header("Cookie", format!("SESSDATA={}", sessdata))
    .header("User-Agent", "Mozilla/5.0")
    .header("Referer", "https://www.bilibili.com");

let resp = client.send(config).await?;
let info: PlayInfo = resp.json()?;
```

### ⚠️ 不适合：音视频文件拉流下载
`send()` 内部使用 `response.text().await` 将**整个响应体一次性读入 `String`**。对几 MB~几 GB 的音视频直链，会直接撑爆内存。原 Go 版 `DownloadMedia` 用的是 `io.TeeReader` 边下边写磁盘——当前 `http_client` **不具备此能力**。

## 4. 已知问题与需要扩充的地方

### 🔴 P0（阻塞编译/运行，必须修）

1. **模块未在 `lib.rs` 注册**
   `src-tauri/src/lib.rs` 目前只声明了 `commands` 和 `recognizer`，没有 `pub mod http_client;`。其他模块无法 `use crate::http_client::HttpClient;`，且此模块当前完全不参与编译（linter 不会报错只是因为没被引用）。
   **扩充动作**：在 `lib.rs` 添加 `pub mod http_client;`。

2. **依赖不匹配：`error.rs` 使用了 `tauri_plugin_http::reqwest`，但 `Cargo.toml` 没有该依赖**
   - `error.rs:1`：`use tauri_plugin_http::reqwest;`
   - `Cargo.toml:20`：`reqwest = { version = "0.12", features = ["json"] }`
   
   二者指向的 `reqwest` 类型不同，编译会报 `reqwest::Error` 类型不兼容（`tauri_plugin_http::reqwest::Error` ≠ `reqwest::Error`）。
   **扩充动作（二选一）**：
   - 统一为 `tauri_plugin_http`：在 `Cargo.toml` 添加 `tauri-plugin-http`，并把 `client.rs` 的 `use reqwest::Client` 改为 `use tauri_plugin_http::reqwest::Client;`
   - 或统一为标准 `reqwest`：把 `error.rs` 改成 `use reqwest;`（推荐，本模块看起来是通用客户端，不依赖 Tauri 插件）。

3. **`with_builder` 的 builder 类型与创建方式不一致**
   `new()` 直接用 `ReqwestClient::builder()`（标准 `reqwest`），而 `error.rs` 却引用 `tauri_plugin_http::reqwest`。若选择标准 `reqwest`，需确保 `client.rs` 与 `error.rs` 引用的是同一个 crate。

### 🟠 P1（功能正确性，针对 B 站场景必须修）

4. **User-Agent 写死为 `HttpClient/1.0`**
   `client.rs:41` 在 `new()` 里固定了 UA。B 站 API 对 UA 有校验，`HttpClient/1.0` 可能被拒绝或返回异常响应。
   **扩充动作**：
   - 方案 A：在 `new()` 改为 `Mozilla/5.0`（B 站接受）；
   - 方案 B（推荐）：保留默认，但让 `RequestConfig.header("User-Agent", ...)` 在 `send()` 中覆盖默认 UA（当前 `send()` 是在默认 builder UA 基础上追加 header，需确认覆盖顺序——建议改用 `with_builder` 并显式设置 UA）。

5. **缺少"强制直连、禁用代理"配置**
   原 Go 版强制 `ProxyURL(nil)` 直连以提升批量解析成功率。当前 `new()` 未设置代理策略，若运行环境存在 `HTTP_PROXY` 等变量，可能走代理导致请求异常。
   **扩充动作**：在 `new()` 或 `with_builder` 中调用 `.no_proxy()` / `.proxy(NoProxy)`。

6. **WBI 签名逻辑缺失**
   B 站 `x/player/playurl` 等接口需要 WBI 签名（`w_rid` + `wts` + MD5）。原 Go 版 `wbi.go` 实现了 `mixinKey` 重排与签名，本模块**未包含**，需在调用方自行实现后作为 query 参数传入。
   **扩充动作**：新增 `bilibili_wbi.rs`（或独立模块），实现 `getWbiKey` + `GetMixinKey` + `WbiSign`；或扩展 `RequestConfig` 增加 `wbi_sign()` 构造方法。

### 🟡 P2（能力扩充，按需求实现）

7. **缺少流式下载（大文件）能力**
   当前 `send()` 用 `response.text()`。需新增流式方法（返回 `reqwest::Response` 或 `bytes_stream`），配合 `tokio::io::copy` 边下边写，用于替代 Go 版 `DownloadMedia` 的音视频拉流。
   **扩充动作**：新增 `async fn download_to_file(url, path, on_progress)` 之类的方法，依赖 `reqwest` 的 `stream` feature 与 `tokio::io`。

8. **缺少 form / raw body / multipart 支持**
   `RequestConfig` 只有 `.json()`。若需要 POST 表单（如某些登录态刷新接口），需扩展 `body` 字段为枚举（`Json / Form / RawBytes`）并在 `send()` 中分支处理。

9. **缺少重试机制**
   原 Go 版 `DownloadMedia` 单一直链最多重试 5 次。当前 `send()` 不自动重试。
   **扩充动作**：`RequestConfig` 增加 `retry: u32`，在 `send()` 中用循环包裹 `req.send()`。

10. **缺少进度回调（下载进度）**
    当前 `on_complete` 只在请求结束后触发，无"下载中进度"。拉流下载时需要边下边汇报百分比。
    **扩充动作**：在流式下载方法中增加 `on_progress(downloaded, total)` 回调。

11. **`CallbackInfo` 未包含错误信息**
    请求失败时 `on_complete` 仍会触发（在 `send()` 第 11 步，但失败时已提前 `?` 返回，不会到达），且 `CallbackInfo` 没有 `error` 字段。建议把回调移到 `Result` 之后，并增加 `error: Option<String>`。

12. **测试用例写死内网地址**
    `client.rs` 底部的 `#[test] test_get_config` 请求 `192.168.66.83:8080`,属于调试残留,应删除或改为 mock。

## 5. 复现 bilibilidown 发请求能力所需补充功能

本节明确：要像 `bilidownload/server` 那样向 B 站服务器发送 HTTP 请求，`http_client` 还缺哪些能力。bilibilidown 实际发出的请求可分为两类：

| 业务 | 接口 | 特殊要求 |
|---|---|---|
| 视频信息 | `x/web-interface/wbi/view` | **必须 WBI 签名** |
| 播放直链 | `x/player/playurl` | **必须 WBI 签名** + `fnval=4048` + `fourk=1` |
| 番剧信息 | `pgc/view/web/season` | 普通 GET |
| 合集列表 | `x/polymer/web-space/seasons_archives_list` | 普通 GET |
| 收藏夹 | `x/v3/fav/resource/list` | 普通 GET，分页 |
| 扫码登录 | `passport-login/web/qrcode/generate` + `/poll` | 普通 GET，需读 Cookie |
| 检查登录 | `x/space/myinfo` | 普通 GET |
| 拉取 WBI key | `x/web-interface/nav` | 普通 GET，正则取 img/sub key |

> 关键：bilibilidown 的请求 = **普通请求**（带 `SESSDATA` Cookie + `Mozilla/5.0` UA + 直连）+ **WBI 签名请求**（view / playurl 强制签名）。

### 5.1 必须实现（不补就调不通 B 站）

1. **WBI 签名能力**（对应 Go 版 `wbi.go`）
   - 现状：完全缺失。但 `getVideoInfo` / `getPlayInfo` 两个核心接口**必须**带 `w_rid`+`wts` 才能返回数据。
   - 需实现：拉 `nav` 取 `imgKey`/`subKey` → 用 `MIXIN_KEY_ENC_TAB`（64 位混淆表）重排取前 32 位 `mixinKey` → 参数排序 + 时间戳 `wts` + MD5 得到 `w_rid`。
   - 建议位置：新增 `http_client/wbi.rs`，暴露 `fn sign(params: &mut Vec<(String,String)>, mixin_key: &str)`，供 `RequestConfig` 注入 query。

2. **UA 写死 `HttpClient/1.0`**（见 4.4）
   - bilibilidown 用 `Mozilla/5.0`，不换会被 B 站拒绝。

3. **强制直连 / `no_proxy()`**（见 4.5）
   - bilibilidown 显式 `ProxyURL(nil)`。运行环境若有 `HTTP_PROXY` 变量会走代理导致解析失败。

4. **从响应读取 Cookie（`SESSDATA`）**
   - 扫码登录 `poll` 接口需在 `response.cookies()` 中提取 `SESSDATA`。
   - 现状：`HttpResponse` 只存了 header map（且多值 key 会丢失），未暴露 `Set-Cookie`。
   - 需新增：`HttpResponse` 增加 `cookies: Vec<(String,String)>` 或迭代 `response.cookies()` 解析。

### 5.2 强烈建议（对齐 bilibilidown 行为，避免踩坑）

5. **请求失败重试**
   - bilibilidown `DownloadMedia` 单一直链重试 5 次；API 也有登录态失效/限流。建议 `RequestConfig` 加 `retry: u32` 字段，在 `send()` 循环包裹 `req.send()`。

6. **统一注入标准请求头**
   - bilibilidown 每个请求都带 `Cookie` / `User-Agent` / `Referer: https://www.bilibili.com`。
   - 建议新增 B 站专用 builder（或 `set_default_headers`），避免每个调用方重复写。

7. **B 站业务码校验**
   - bilibilidown 会判定返回 JSON 的 `code != 0` 为失败（如 `-404` 无效）。
   - 建议 `send_expect_success` 之外加 `expect_bilibili_code()`，解析 body 的 `code` 字段。

8. **WBI key 缓存**
   - bilibilidown 把 `wbi_key` 存 SQLite、24h 刷新。纯 Rust 端至少用内存缓存（带过期时间），避免每次请求都拉 `nav`。

### 5.3 可选（下载阶段才需要，非"发请求"本身）

9. **流式请求**（替代 `DownloadMedia` 拉流，见 4.7）
   - 属 `http_client` 能力延伸：当前 `text()` 全量读内存，下音视频必爆；需 `bytes_stream` + 进度回调。

### 5.4 一句话总结

要"像 bilibilidown 那样向 B 站发请求"，`http_client` **必须**补齐：WBI 签名、正确 UA、强制直连、响应 Cookie 读取；**强烈建议**补齐：重试、标准头预设、B 站业务码校验、WBI key 缓存。其中 **WBI 签名是第 1 优先级** —— 没有它，最核心的视频信息 / 播放直链两个接口根本拿不到数据。

## 8. 最小可用示例（修复后）

```rust
// lib.rs 中添加：
pub mod http_client;

// 调用方：
use crate::http_client::{HttpClient, HttpMethod, RequestConfig};

#[tauri::command]
async fn fetch_play_info(bvid: String, cid: u64, sessdata: String) -> Result<String, String> {
    let client = HttpClient::new(); // 修复后 UA 应为 Mozilla/5.0 且 no_proxy
    let config = RequestConfig::new("https://api.bilibili.com/x/player/playurl")
        .method(HttpMethod::GET)
        .query("bvid", bvid)
        .query("cid", cid.to_string())
        .query("fnval", "4048")
        .query("fourk", "1")
        .header("Cookie", format!("SESSDATA={}", sessdata))
        .header("Referer", "https://www.bilibili.com");

    let resp = client.send_expect_success(config)
        .await
        .map_err(|e| e.to_string())?;
    Ok(resp.body)
}
```
